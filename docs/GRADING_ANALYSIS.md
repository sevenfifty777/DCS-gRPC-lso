# Grading Design Record

**Status:** Implemented

**Current specification:** [GRADING_REFERENCE.md](GRADING_REFERENCE.md)

## Purpose

This document records the grading migration that replaced the original fixed-foot tiers and
nonstandard `Fair`/`NG` labels with the current degree-based, simplified NAVAIR-style model. It is a
design-history document, not the operator reference.

## Implemented changes

- `GateDatum` stores glideslope and lineup in both degrees and feet. Degrees drive grading; feet are
  retained for chart and Discord presentation.
- Samples are taken once on the first inbound crossing of 3/4, 1/2, and 1/4 nm while below 500 ft
  above the deck.
- `PassGrade` exposes standard display labels and points:

  | Enum | Label | Points |
  |---|---|---:|
  | `Unicorn` | `_OK_` | 5.0 |
  | `Ok` | `OK` | 4.0 |
  | `OkParentheses` | `(OK)` | 3.0 |
  | `NoGrade` | `--` | 2.0 |
  | `Cut` | `C` | 0.0 |
  | `Bolter` | `B` | 2.5 |
  | `WaveoffPilot` | `WO` | 1.0 |

- The base recovered grade is selected from the worst GS/LU deviation across available gates.
- `_OK_` upgrades an otherwise `OK` pass only when wire 3 is reported/estimated and groove time is
  15.0 through 18.99 seconds.
- A quarter-nm glideslope deviation below -2.5 degrees produces `C`.
- Special outcomes override normal gate grading. A hook-up qualification bolter uses recovered gate
  grading when a cable can be estimated; when no cable can be estimated it receives `B`.
- Grade label/points are used by charts, terminal output, Discord, SQLite, and the HTTP board. JSON
  serializes Rust enum names rather than display labels.

## Deliberate simplifications

The implementation is not a complete NAVAIR or MOOSE Airboss evaluator:

- It grades three snapshots rather than a continuous/call-based pass history.
- AoA is recorded and visualized but not penalized.
- There is no LSO-called waveoff state, own-waveoff distinction, power call, aircraft-specific grade
  modifier, or accumulated deviation notation generated by LSO.
- `C` is a geometric low-at-the-ramp proxy; the code does not track a human LSO waveoff followed by
  a landing.
- DCS `LandingQualityMark` text is retained and translated separately; it is not used to compute the
  GS/LU base grade except for wire-number override.

## Verification surface

`src/grading.rs` contains focused tests for thresholds, points, special outcomes, Unicorn criteria,
and missing-gate behavior. `src/tests.rs` replays five captured ACMI recordings to validate wire
estimation across all four cables and multiple aircraft types.
